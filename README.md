# SAR-ULRTC-CR

PyTorch research code for **SAR-ULRTC-CR**, an unrolled low-rank tensor-completion approach to SAR-guided cloud removal in multispectral satellite images.

The repository currently contains model variants, preprocessing notebooks, training and evaluation entrypoints, and pretrained checkpoints for two datasets:

- **SEN12MS-CR**: 13-band Sentinel-2 imagery with 2-channel Sentinel-1 SAR data.
- **SMILE-CR**: 6-band Landsat imagery with 2-channel Sentinel-1 SAR data.

Both variants also consume a 3-channel translated image generated by the included CycleGAN workflow.

## Current implementation

The network is implemented in [`model/main_net.py`](model/main_net.py) as an unrolled sequence of robust-PCA/tensor-completion blocks:

| Dataset | Model class | Training entrypoint | Evaluation entrypoint | Included checkpoint |
| --- | --- | --- | --- | --- |
| SEN12MS-CR | `SAR_ULRTC_CR` | `model/train_SEN12MSCR.py` | `model/test_SEN12MSCR.py` | `ckpts_SEN12MSCR/epoch_200.pth` |
| SMILE-CR | `SAR_ULRTC_CR_SMILECR` | `model/train_SMILECR.py` | `model/test_SMILECR.py` | `ckpts_SMILECR/epoch_100.pth` |

The default configuration uses 10 unrolled iterations (`--N_iter 10`). The code calls `.cuda()` directly and creates internal tensors on CUDA, so an NVIDIA GPU and a working CUDA installation are currently required.

## Environment

The supplied Conda environment uses Python 3.9, PyTorch 2.2.2, and CUDA 11.8.

```bash
conda env create -f environment.yaml
conda activate SAR-ULRTC-CR
```

Run the train/test commands from `model/`. This is necessary because the scripts use local imports and their default data/checkpoint paths are relative to that directory.

```bash
cd model
```

## Data preparation

The raw datasets are not included. Use the repository notebooks to prepare them:

- [`dataset/SEN12MSCR_dataset.ipynb`](dataset/SEN12MSCR_dataset.ipynb)
- [`dataset/SMILECR_dataset.ipynb`](dataset/SMILECR_dataset.ipynb)
- [`dataset/CycleGAN/CycleGAN.ipynb`](dataset/CycleGAN/CycleGAN.ipynb) for generating the translated-image inputs

Pretrained CycleGAN weights are included under `dataset/CycleGAN/checkpoints/cyclegansen12/`.

### SEN12MS-CR

The active SEN12MS-CR loaders expect matching filenames across the cloudy input, cloud-free target, SAR, mask, and translated-image directories. The base NPY layout is:

```text
SEN12MS-CR_1/
├── SEN12MSCR_train_input_npy/
├── SEN12MSCR_train_gt_npy/
├── SEN12MSCR_train_sar_npy/
├── SEN12MSCR_train_mask_npy/
├── SEN12MSCR_test_input_npy/
├── SEN12MSCR_test_gt_npy/
├── SEN12MSCR_test_sar_npy/
├── SEN12MSCR_test_mask_npy/
├── SEN12MSCR_val_input_npy/
├── SEN12MSCR_val_gt_npy/
├── SEN12MSCR_val_sar_npy/
└── SEN12MSCR_val_mask_npy/
```

For `--data_mode full`, the train and test directory names end in `_npy_full` instead of `_npy`. Validation always uses the unsuffixed directories shown above.

There are currently two translated-input conventions in `model/dataLoader.py`:

- `SEN12MSCR_0`, used by training, reads PNG files from `SEN12MSCR_<split>_translated/` or `SEN12MSCR_<split>_translated_full/`.
- `SEN12MSCR_1`, referenced by evaluation, reads NPY files from `SEN12MSCR_<split>_translated_partial_npy/` or `SEN12MSCR_<split>_translated_full_npy/`.

### SMILE-CR

The SMILE-CR loaders expect this split layout:

```text
SMILE-CR-npy/
├── TrainData/TrainData/
├── ValData/ValData/
└── TestData/TestData/
```

Each final split directory contains:

```text
CloudLandsat_2020/       # Cloudy 6-band NPY inputs
Landsat-8_2020/          # Cloud-free 6-band NPY targets
MODIS_2020/              # Optional MODIS NPY data
Mask/                    # Cloud-mask NPY files
Sentinel-1_2020-De/      # 2-channel SAR NPY files
```

`SMILECRNumpyDataset` (training) reads translated PNG files from `Translated/`. `SMILECRNumpyDataset_1` (evaluation) reads translated NPY files from the split-specific `SMILECR_<split>_translated_full_npy/` directory.

## Training

The following commands reflect the current CLI options. See [Current code status](#current-code-status) before running them.

### SEN12MS-CR

```bash
cd model
python train_SEN12MSCR.py \
  --train_path /path/to/SEN12MS-CR_1 \
  --save_path ../ckpts_SEN12MSCR \
  --data_mode full \
  --num_epoch 200 \
  --batch_size 1 \
  --N_iter 10 \
  --omega 0.5
```

`--data_mode partial` uses the partial directory set and randomly selects 5,000 training samples. It also writes the chosen indices to `model/seed/train_5k_subset_indices.pth`, so create `model/seed/` before using that mode.

### SMILE-CR

```bash
cd model
python train_SMILECR.py \
  --train_path /path/to/SMILE-CR-npy \
  --save_path ../ckpts_SMILECR \
  --num_epoch 100 \
  --batch_size 1 \
  --N_iter 10 \
  --w 1.0
```

Both training scripts support `--resume /path/to/epoch_N.pth`, `--checkpoint_freq`, `--loss_freq`, and `--set_lr`. Checkpoints contain the epoch, model state, and optimizer state. A learning-curve image and `training_log.txt` are written to the selected checkpoint directory.

## Evaluation

### SEN12MS-CR checkpoint

```bash
cd model
python test_SEN12MSCR.py \
  --data_path /path/to/SEN12MS-CR_1 \
  --ckpt_dir ../ckpts_SEN12MSCR \
  --epoch 200 \
  --N_iter 10 \
  --data_mode full \
  --gpu 0 \
  --fig_mode all
```

The current SEN12MS-CR entrypoint evaluates the selected `--epoch`. `--params` additionally reports parameter and FLOP estimates through THOP.

### SMILE-CR checkpoint

```bash
cd model
python test_SMILECR.py \
  --data_path /path/to/SMILE-CR-npy \
  --ckpt_dir ../ckpts_SMILECR \
  --epoch 100 \
  --N_iter 10 \
  --gpu 0 \
  --fig_mode all \
  --test_mode single
```

For SMILE-CR, `--test_mode all --skip_epochs N` evaluates every checkpoint at or after epoch `N` and reports the best checkpoints by PSNR, SAM, and SSIM.

Set `--fig_mode none` to compute metrics without writing comparison images. Otherwise, outputs are written below `model/results_SEN12MSCR/` or `model/results_SMILECR/`.

Both evaluators report:

- RMSE
- MAE
- PSNR
- spectral angle mapper (SAM, in degrees)
- SSIM

## Current code status

The repository is a research-code snapshot, and the checked-in entrypoints currently have naming inconsistencies that must be resolved before execution:

1. The SEN12MS-CR scripts import `RPCA_Net_4_stages_SAR_Trans_RGB_9`, but `model/main_net.py` defines the corresponding model as `SAR_ULRTC_CR`.
2. The SMILE-CR scripts import `RPCA_Net_4_stages_SAR_Trans_RGB_SMILECR_9`, but `model/main_net.py` defines the corresponding model as `SAR_ULRTC_CR_SMILECR`.
3. `model/test_SEN12MSCR.py` instantiates `SEN12MSCR_1` but currently imports only `SEN12MSCR_0`.
4. The implementation is CUDA-only; CPU execution is not currently supported by the entrypoints or model initialization.
5. The model `forward` methods accept a direct `SAR` tensor, but the current block calls use the cloudy optical input and translated-image prior; the direct `SAR` argument is not otherwise referenced.

These points describe the repository as checked in; the commands above are the intended workflows once the import names are aligned.
